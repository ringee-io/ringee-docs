---
title: Inbound events
description: "Push contacts and companies from your CRM into Ringee"
openapi: "POST /api/integrations/custom/webhook"
---

Send everything your CRM knows about a contact or company to a single Ringee endpoint. Ringee upserts the record, links it to your `externalId`, and makes it callable.

Pick the event you are sending in the request body above — each one has its own `data` shape.

Every request uses the shared envelope:

| Field        | Type   | Required | Description                               |
| ------------ | ------ | -------- | ----------------------------------------- |
| `event`      | string | Yes      | One of the four inbound event names below |
| `eventId`    | string | Yes      | Stable unique id for this logical event   |
| `occurredAt` | string | Yes      | ISO-8601 timestamp from your system       |
| `data`       | object | Yes      | Event-specific payload                    |

## Reading the response

The endpoint returns **202 Accepted** for any well-formed, authenticated request. The real result is in the JSON body.

| Status                                                  | Meaning                                          | What to do                                                                                      |
| ------------------------------------------------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| <span className="rg-badge rg-get">processed</span>      | The event was applied.                           | Mark the sync as successful.                                                                    |
| <span className="rg-badge rg-neutral">skipped</span>    | Ringee already recorded this `eventId`.          | Do not process it again. Preserve the original result; retry a corrected failure with a new id. |
| <span className="rg-badge rg-destructive">failed</span> | The event was accepted but could not be applied. | Show `message`, mark as a sync failure, fix and resend with a **new** `eventId`.                |

<Warning>
  A `202` status code only means the transport was accepted. Do not treat it as
  a successful sync without checking `status` in the body.
</Warning>

## Event examples

<Tabs>
<Tab title="contact.upserted">

Create or update a contact from your CRM's current state.

```json
{
  "event": "contact.upserted",
  "eventId": "crm_01HX5Z7K8MZP1Q4V0G9YJ2RH3T",
  "occurredAt": "2026-05-23T14:30:00.000Z",
  "data": {
    "externalId": "ext_contact_42",
    "phoneNumber": "+14155550123",
    "firstName": "Ada",
    "lastName": "Lovelace",
    "email": "ada@example.com",
    "companyExternalId": "ext_company_7",
    "jobTitle": "Founder",
    "ownerEmail": "rep@example.com",
    "customFields": { "tier": "vip" }
  }
}
```

| `data` field                                | Type   | Required | Description                                                           |
| ------------------------------------------- | ------ | -------- | --------------------------------------------------------------------- |
| `externalId`                                | string | Yes      | Stable contact id in your system                                      |
| `phoneNumber`                               | string | Yes      | Dialable number; normalized toward E.164 when possible                |
| `name`, `firstName`, `lastName`, `fullName` | string | No       | Available name representations                                        |
| `email`                                     | string | No       | Primary email                                                         |
| `companyExternalId`                         | string | No       | External company id to link                                           |
| `companyName`                               | string | No       | Fallback company name when a linked company is unavailable            |
| `jobTitle`                                  | string | No       | Contact position or title                                             |
| `ownerEmail`                                | string | No       | Resolves a Ringee member in an organization workspace                 |
| `ownerExternalId`                           | string | No       | Accepted in the snapshot, but not currently used for owner resolution |
| `source`                                    | string | No       | Lead source label                                                     |
| `customFields`                              | object | No       | Arbitrary contact fields                                              |
| `crmMetadata`                               | object | No       | Provider-specific metadata                                            |

<Note>
  **Deduplication order:** `externalId` first, then `phoneNumber` within the
  same workspace. Sending `null`, `undefined` or empty strings does **not**
  overwrite existing values — omit a field to leave it untouched.
</Note>

<Info>
  In an organization workspace, an unknown `ownerEmail` leaves the contact
  unassigned. In a personal workspace, the integration owner is used.
</Info>

</Tab>

<Tab title="company.upserted">

```json
{
  "event": "company.upserted",
  "eventId": "crm_01HX5Z8FYBKD7QY5W3JN9NF2EA",
  "occurredAt": "2026-05-23T14:30:05.000Z",
  "data": {
    "externalId": "ext_company_7",
    "name": "Babbage Engines Ltd.",
    "domain": "babbage.example.com",
    "industry": "Hardware",
    "size": "11-50"
  }
}
```

| `data` field   | Type   | Required | Description                                       |
| -------------- | ------ | -------- | ------------------------------------------------- |
| `externalId`   | string | Yes      | Stable company id in your system                  |
| `name`         | string | Yes      | Display name                                      |
| `legalName`    | string | No       | Registered legal name                             |
| `domain`       | string | No       | Primary domain and secondary deduplication signal |
| `industry`     | string | No       | Industry label                                    |
| `size`         | string | No       | Headcount band, such as `11-50`                   |
| `phone`        | string | No       | Main phone                                        |
| `website`      | string | No       | Homepage URL                                      |
| `source`       | string | No       | Source label                                      |
| `customFields` | object | No       | Arbitrary company fields                          |
| `crmMetadata`  | object | No       | Provider-specific metadata                        |

<Note>
  **Deduplication order:** `externalId`, then `domain` within the same
  workspace. As with contacts, `null`, `undefined` and empty strings do not
  clear existing values.
</Note>

</Tab>

<Tab title="contact.deleted">

Marks the contact as archived in Ringee.

```json
{
  "event": "contact.deleted",
  "eventId": "crm_01HX5Z9MQ7G3T2DR0NXJW1B8VC",
  "occurredAt": "2026-05-23T14:35:00.000Z",
  "data": { "externalId": "ext_contact_42" }
}
```

<Info>
  Ringee never deletes the underlying contact. Call history, notes, callbacks
  and meetings are preserved — only the integration's link is archived.
  Re-sending `contact.upserted` with the same `externalId` un-archives it. If no
  link exists, the delete is a successful no-op.
</Info>

</Tab>

<Tab title="company.deleted">

```json
{
  "event": "company.deleted",
  "eventId": "crm_01HX5ZA1H4T6N2DR9CB7YP6F0K",
  "occurredAt": "2026-05-23T14:35:30.000Z",
  "data": { "externalId": "ext_company_7" }
}
```

This archives only the link created by this integration. Historical company relationships remain available in Ringee. If no link exists, the delete is a successful no-op.

</Tab>
</Tabs>

## Sending events well

<AccordionGroup>
<Accordion title="Do not send on every render or save" icon="rotate">

Sync only when a field Ringee cares about actually changes: name, phone, email, company, job title, owner. Sending an event on every UI update wastes quota and makes your logs unreadable.

</Accordion>

<Accordion title="Use E.164 phone numbers" icon="phone">

Ringee normalizes what it can, but `+14155550123` always wins over `(415) 555-0123`. A number Ringee cannot normalize may fail dedup against an existing contact.

</Accordion>

<Accordion title="Never re-send what Ringee wrote" icon="arrows-rotate">

If your CRM record was created or updated by a Ringee webhook, do not send it back. Store a `sync_origin` marker on those rows and skip them. See [Build an integration](/api/build-an-integration#prevent-sync-loops).

</Accordion>

<Accordion title="Queue before you send" icon="layer-group">

Write the event to a local outbox table first, then attempt delivery. A contact save in your CRM should never fail because Ringee is momentarily unreachable.

</Accordion>
</AccordionGroup>
